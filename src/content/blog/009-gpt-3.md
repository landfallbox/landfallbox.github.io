GPT-1 证明了预训练 + 微调这条路是可行的，但它的光芒很快就被 Google 的 BERT 盖住了。

BERT 和 GPT-1 同样使用 Transformer，同样采用先预训练再适配下游任务的思路，但它们在架构选择上走向了不同方向。GPT-1 只保留 Decoder，只能从左到右单向阅读；BERT 则只保留 Encoder，可以同时看到一个词前后的上下文。为了让 Encoder 在预训练时学会语言理解，BERT 采用了 掩码语言模型（Masked Language Modeling，MLM）：随机遮住句子中的一部分词，让模型根据前后文把它们猜回来。

这个设计非常适合理解类任务。在 GLUE 这样的榜单上，BERT 很快超过 GPT-1，甚至让很多人相信：GPT 这种单向生成路线可能只是一个旁支，而 BERT 代表的双向理解路线才是 NLP 的正统。毕竟，直觉上双向理解更符合人类的语言处理方式。那段时间，学术界和工业界几乎都在做 BERT 的改进版本，或者把 BERT 应用到搜索、推荐、问答、客服等具体业务中。

GPT 路线看起来被压住了。

但 GPT 有一个 BERT 做不到的能力：生成长文本。

## GPT-2 的过渡

2019 年，OpenAI 发布 GPT-2。它的论文标题叫《Language Models are Unsupervised Multitask Learners》，意思是语言模型是无监督的多任务学习器。这个标题其实已经把 OpenAI 的野心写得很清楚了：他们不满足于让一个模型先预训练，再针对每个任务微调。他们想训练出一个通才模型，让它不用专门训练，只靠自然语言上下文就能完成各种任务。

这种能力后来被称为 Zero-Shot。

不过在当时，GPT-2 的能力还不稳定。它在语言建模和长文本生成上表现非常惊艳，能写出连贯的新闻、故事和段落；但在翻译、问答、阅读理解等标准任务上，它并没有真正战胜 BERT。GPT-2 展示了一个方向，却还没有证明这个方向一定能赢。

这时，OpenAI 的 CEO 山姆·奥特曼（Sam Altman）做了一件非常关键的事。他没有让 GPT-2 只是作为一个“不如 BERT 的模型”被遗忘，而是声称“模型太危险，暂不完全开源”，把 GPT-2 包装成了一个值得全行业关注的危险技术。OpenAI 先发布小模型，再分阶段释放更大的模型，让 GPT-2 的热度持续了很久。

这为 OpenAI 争取到了时间，并通过一系列商业上的举措为训练 GPT-3 积累了资金和资源。

## GPT-3 的工程挑战

GPT-3 发布于 2020 年。它最惊人的地方是参数规模。GPT-1 只有 0.117 B 参数，GPT-2 最大版本是 1.5 B 参数。GPT-3 一下子把规模提高到了 175 B。这个数字不只是看起来夸张，它直接把训练过程推入了一个新的时代。

训练 GPT-3 面临的第一个问题，是模型太大，单块 GPU 装不下。

一个参数在训练时不只需要保存参数本身，还要保存梯度、优化器状态、中间激活值等信息。参数量变成 175 B 之后，训练所需显存远远超过单张显卡的容量。解决办法只能是把模型拆开，让很多张 GPU 共同训练同一个模型。

解决方法是三种并行策略的组合。

**数据并行**：把一批训练数据切成很多份，分给不同 GPU，每张 GPU 都保存一份完整模型，各自计算梯度，最后再同步更新参数。数据并行要求每张 GPU 都能放下完整模型，所以对于 GPT-3 这种模型来说还不够。

**模型并行**：既然一张 GPU 放不下整个模型，就把模型的不同部分切到不同 GPU 上。例如某一层 Transformer 的矩阵乘法可以被拆开，让多张 GPU 分别计算一部分结果，再把结果合并。这相当于把一个巨大模型切成很多块，分布在很多设备上。

**流水线并行**：Transformer 有很多层，可以把前几层放在一组 GPU 上，中间几层放在另一组 GPU 上，后面几层再放在别的 GPU 上。数据像流水线上的零件一样，从第一组 GPU 流到最后一组 GPU。这样可以让不同 GPU 同时工作，减少等待时间。

这些方法听起来只是把大模型切开，但真正困难的地方在于协调。成千上万张 GPU 一起训练时，任何一张卡掉线、任何一次通信延迟、任何一次同步失败，都可能拖慢甚至中断整个训练。训练大模型不再只是写模型代码，而是一个巨型分布式系统工程。

第二个问题，是数据太脏。

GPT 的训练目标是预测下一个词。这个任务本身不需要人工标注，所以理论上可以使用互联网上的海量文本。但互联网文本并不等于高质量知识。网页里有广告、灌水、重复内容、乱码、低质量论坛回复、垃圾站点和机器生成文本。如果直接把这些内容喂给模型，模型不但学不到高质量语言，反而可能学会一堆坏习惯。

OpenAI 的做法，是用高质量数据作为样本，训练一个数据筛选器。GPT-2 曾经使用过来自 Reddit 高赞链接的数据，因为这些链接往往指向质量较高的网页。OpenAI 以这类数据为参照，从更大规模的爬虫语料中筛选出更接近高质量文本的内容，再去重、清洗、过滤，最终形成 GPT-3 的训练数据。

这件事说明了一个很重要的规律：大模型不是只要“吃得多”就行，还要“吃得好”。数据质量会直接决定模型能力的上限。如果训练数据里充满重复和噪声，模型的参数再多，也只是在更认真地学习垃圾。时至今日，数据质量仍然是大模型训练的核心问题之一。

第三个问题，是训练不稳定。

小模型训练失败，最多是重新跑一次实验；超大模型训练失败，损失就非常夸张。一次训练可能持续数周甚至数月，消耗大量 GPU 时间。如果训练中途 loss 突然暴涨、梯度爆炸，或者某些节点异常导致任务中断，前面烧掉的成本就可能白费。

因此，训练 GPT-3 需要一整套稳定性工程。比如通过合适的学习率策略避免训练初期震荡，通过梯度裁剪限制异常梯度，通过混合精度训练提升效率并控制数值误差，通过 checkpoint 定期保存模型状态。checkpoint 的频率还必须权衡：保存太少，一旦出错会丢掉大量进度；保存太频繁，又会占用存储和通信资源，拖慢训练。

于是，以 GPT-3 为标志，大模型训练不只是算法竞赛，而是一个综合工程问题。它需要算法、数据、系统、硬件和资金的共同参与。

## Scaling Law

在 GPT-3 正式发布之前，OpenAI 先发表了一篇非常重要的论文：《Scaling Laws for Neural Language Models》。这篇论文试图回答一个朴素但关键的问题：把模型做大，效果真的会持续变好吗？

在这篇论文之前，很多人相信“大力出奇迹”，但这种相信更像经验判断。Scaling Law 把这种经验变成了可以预测的规律。

论文的核心思想可以简化为一个公式：

$$
L(x) \propto \frac{1}{x^\alpha}
$$

这里的 $L$ 表示模型的 loss；$x$ 表示投入的资源，可以是参数量、数据量或计算量；$\alpha$ 是一个幂律指数。这个公式表达的意思是：当资源投入增加时，模型的 loss 会按照幂律规律下降。

更直白地说，模型越大，数据越多，算力越强，模型就越聪明。而且这种提升不是随机的，而是可以预测的。

由于训练 GPT-3 的成本太高，如果没有理论支撑，这件事就像一次豪赌。Scaling Law 告诉他们：只要参数、数据和算力按合适比例扩大，模型能力大概率会按预期提升。

此外，GPT-3 还带来了又一次范式变化：从 “预训练 + 微调” 转向 “预训练 + 提示词”。

从 GPT-1 开始，主流 NLP 模型的范式是 “预训练 + 微调”。先训练一个通用模型，再针对具体任务分别标注数据并微调。这个方式比旧时代“每个任务从头训练一个模型”先进很多，但它仍然依赖人工标注数据，也仍然需要为每个任务维护一个独立的模型副本。

GPT-3 展示了另一种可能：一个足够大的语言模型，可以通过提示词直接完成任务。

比如翻译任务，不一定要再专门训练翻译模型，只需要输入：

```text
把下面这句话翻译成中文：
The model learns from large-scale text data.
```

模型就会继续生成中文翻译。

GPT-3 强大的 Few-Shot / Zero-Shot 能力，让它可以在不微调的情况下，直接通过自然语言提示完成各种任务。于是，Prompt 开始取代 Fine-tuning，成为 NLP 领域新的范式。

不过，GPT-3 的本质仍然是一个文本补全模型。它的训练目标是预测下一个词，而不是理解用户意图、遵守用户指令、给出可靠答案。如果提示词写得不好，GPT-3 可能会给出不符合用户期望的回答。毕竟，训练目标决定了它只是在判断接下来最可能出现什么文本。

另一个问题是幻觉。既然 GPT-3 的训练目标是预测下一个词，它就没有天然的事实判断能力。它只能根据上下文生成最可能的文本，而不是根据事实生成文本。对于写故事、写广告文案来说，这种能力有时甚至是优点。但对于需要准确性的场景，它就是严重风险。

此外，GPT-3 从互联网文本中学习语言，互联网里既有知识，也有偏见、攻击性内容和危险信息。模型学会了语言模式，却没有学会什么可以说，什么不可以说。这个问题最终催生出了一个新的研究课题：对齐。
