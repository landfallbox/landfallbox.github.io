OpenAI 没有公开 GPT-4V 的完整架构，所以我们不能把任何一种复现方案直接等同于 GPT-4V 本身。但从 CLIP、ViT 以及后来大量开源多模态模型的路线来看，GPT-4V 可以被抽象成一种如下所示的多模态实现：

```text
图像 -> 视觉编码器 -> visual tokens -> 投影层 -> LLM -> 回答
```

图像进入视觉编码器（可能是 CNN，ViT，或者是 CLIP 中的图像编码器），从像素矩阵变成一组向量表示。向量经过投影层映射到语言模型的语义空间，变成可以被 LLM 理解的 tokens。最终让模型可以像处理文字上下文一样处理图像上下文，并生成回答。

这条路线可以最大程度复用已经训练好的大语言模型，也可以复用已经训练好的视觉编码器，可以快速地在工程上实现多模态能力。

GPT-4V 刚发布时技惊四座，但用户很快发现了其缺点。它似乎不太识数，总是会把图像里面物体的个数数错，它也不太认字，一张图片里面的文字只能笼统的说出是一张写满文字的纸，而无法分辨纸上第三行写了什么字。

人们逐渐发现这是视觉编码器的天然局限。视觉编码器把图像按块分割，这个过程可能把某个完整的物体切开，导致特征分离，让视觉编码器无法正确的数出物体的数量（物体可能被切断了），让视觉编码器无法正确的识别文字（字只显示了局部或者因为分辨率原因糊掉了）。总的来说，模型更擅长回答整体语义问题，而不擅长回答精确视觉问题。

此外，CLIP 的做法默认将文本作为官方语言，要求 visual tokens 映射到语言模型的语义空间，意味着必然存在一定程度的信息损失。这种做法实际是语言中心主义的。虽然为文本模型带来了多模态能力，但也带来了不可避免的信息损失。

## 图文交错

在嵌入式的多模态和原生多模态之间，有一个重要的中间阶段：图文交错训练。

CLIP 学到的是图像和文本之间的对应关系。它更像是在学习一本图文词典：一张图对应一段文字，一段文字对应一张图。

但现实世界里的多模态信息并不是这样孤立出现的。我们读网页时，常常是一段文字下面跟着一张图，图片后面又接着解释。

这时，模型需要理解的不只是图像和文本是否匹配，而是图像如何参与上下文。

DeepMind 的 Flamingo 在这条路线上迈出了重要一步。他们在论文《Flamingo: a Visual Language Model for Few-Shot Learning》中首次提出了这一方法，使用交错数据进行训练，让模型在文本和图像混合出现的序列中学习。例如：

```text
[文本] 今天我去机场
[图片] 机场候机厅
[文本] 结果航班延误，我只好吃了
[图片] 一个汉堡
[文本] 这个当晚饭
```

这种训练方式比单纯的图文配对更接近人类真实使用信息的方式。图像不再只是被描述的对象，而是上下文链条中的一环。

它还能帮助模型理解指代关系。比如用户先发一张车的图片，然后问 “这个多少钱？” 模型必须知道 “这个” 指的是前面的图片，而不是文本中的某个词，从而给出正确的回答，而不是问 “哪个？”。

从这个角度看，图文交错训练已经开始动摇纯粹的文本中心范式。模型不再只是把图片翻译成一句话，而是开始学习如何让图像和文字共同构成上下文。

以此为基础，Google 在 2023 年 12 月推出了 Gemini 1.0，在业界首次推出了从零开始构建的原生多模态模型。

在此之后，OpenAI 推出了 GPT-4o，以 DeepMind 2017 年的论文 《Neural Discrete Representation Learning》 为基础，使用 VQ-VAE 训练了一个视觉编码器，并将其与 GPT-4o 结合，进一步支持了文字、图像、视频、音频等各种模态的输入。
